# data-workflow-ms

R project for analyzing VERA forecast challenge scores, comparing the FLARE data-assimilation model against a climatology null model. The code in this repository can be used to generate the forecast analysis figure in "A real-time, automated ecological monitoring workflow and data publication program to enable daily ecosystem forecasting" by Carey et al.  

## Files

- **`data-workflow-ms.Rproj`** — RStudio project file (2-space indent, UTF-8).
- **`vera_analysis.qmd`** — Quarto document with the analysis (see below).
- **`vera_analysis.html`** — Rendered HTML report, self-contained (`embed-resources: true`, so figures are inlined rather than written to a companion `_files/` directory).
- **`figure_3.png`** — Output figure generated by the document: mean CRPS vs. forecast horizon, faceted by variable.
- **`.gitignore`** — Standard R/RStudio ignores plus Quarto build artifacts (`.quarto/`, `*_files/`, `*_cache/`, `*.knit.md`).

## `vera_analysis.qmd`

Quarto document (HTML output, with a table of contents and folded code chunks) that pulls forecast scores from the VERA4cast bundled-parquet archive (hosted on OSN/S3) and compares forecast skill between two models at site `fcre` (Falling Creek Reservoir, Virginia, USA).

**Sections:**

1. **Load data** — Opens the remote parquet dataset via `arrow::open_dataset()` and filters to:
   - Models: `climatology` (null model) and `glm_aed_flare_v3` (FLARE with daily data assimilation)
   - Variables: water temperature, chlorophyll-a, Secchi depth, dissolved oxygen
   - Site: `fcre`
2. **Clean and pair forecasts** — Relabels variables/models with display-friendly names, computes forecast `horizon` in days (`datetime - reference_datetime`), and restricts to horizons ≤ 30 days. Pivots so each `reference_datetime`/`horizon`/`variable` has both models' CRPS side by side, dropping rows where either model is missing (ensures a fair paired comparison), then pivots back to long format.
3. **Summarize** — Computes mean CRPS (`summary_df`) per model/horizon/variable, plus sanity checks on sample size (`n`) and the date range of `reference_datetime` covered.
4. **Skill comparison** — For each variable, finds the maximum horizon at which FLARE's mean CRPS beats climatology's (lower CRPS = better).
5. **Figure 3** — Renders and saves `figure_3.png`: mean CRPS vs. horizon, one facet per variable, colored by model type, saved at 6×4 in, 300 dpi.

**Dependencies:** `tidyverse`, `arrow` (with S3 support), [Quarto CLI](https://quarto.org).

**Rendering:** `quarto render vera_analysis.qmd`

**Data source:** `s3://anonymous@bio230121-bucket01/vera4cast/scores/bundled-parquet` (public, anonymous access via OSN endpoint `amnh1.osn.mghpcc.org`).
